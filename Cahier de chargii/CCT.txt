  version     String
  size        String
  image       String
  fileUrl     String
  status      String   // Stable / Beta / New
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt
}

8. SERVICE API (FRONTEND → SUPABASE)

Exemple fetch produits

import { supabase } from "../config/supabase";

export async function getProducts() {
  const { data, error } = await supabase
    .from("products")
    .select("*")
    .order("createdAt", { ascending: false });

  if (error) throw error;
  return data;
}

14. RÈGLES TECHNIQUES GÉNÉRALES

À FAIRE

- Code modulaire (components réutilisables)
- Structure claire (pages / services / store)
- Upload fichiers via Admin uniquement
- Validation des données avant insertion DB
- Filtres via requêtes optimisées
- Images compressées
- Chargement lazy (images / ads)
- Gestion erreurs API
- UI responsive mobile-first

À ÉVITER

- Upload direct public
- Requêtes DB lourdes
- Trop de relations complexes
- Stockage inutile
- Ads intrusives
- Scripts bloquants
- Téléchargement non sécurisé
- Base trop chargée

---

15. SÉCURITÉ

Base Supabase

- RLS activé (Row Level Security)
- Tables protégées
- Écriture uniquement via Admin
- Lecture publique limitée aux produits

Storage

- Fichiers signés (signed URLs)
- Upload Admin uniquement
- Extensions contrôlées
- Scan fichiers avant publication

Frontend

- Pas de clé privée exposée
- Variables env sécurisées
- Validation input utilisateur
- Protection XSS / injection
